Global per-client rates

Applied to every active WebSocket session, regardless of event kind. Limit is the sustained per-second rate; burst is how many actions can fire back-to-back before the limit kicks in. Burst is usually 2–3× the limit for bursty workloads.

Max event size

Applied to event validation AND the WebSocket message buffer — events bigger than this get rejected at ingest.
Reference: a signed kind-1 short note with <100 characters of content is roughly 400 bytes. Default 512 KB easily fits the largest realistic events (long follow lists, profile metadata with embedded images as data URIs); tighten it if you see abuse.

Per-category rates

Override the global EVENT rate for whole NIP-01 ranges. Enable a category to make its limit/burst kick in; leave disabled to use the global EVENT rate above. Sensible defaults pre-fill on enable.
